# 월 1회 관광정보 동기화

사용자 요청: 일 1회 대신 월 1회. 매월 1일 오전 6시(KST) 기준. 최초 대상은 기존 200건으로 유지하며 신규 콘텐츠를 자동 추가하지 않는다. 실제 서버 예약 등록은 배포 이후 적용한다.

| 항목 | 추천 처리 |
|---|---|
| 이름·주소·좌표 | 변경 대조 후 위치 불일치 시 우선 검수 |
| 시간·휴무·요금·주차 | 변경된 값과 근거를 다시 확인 |
| 무료·아이·반려동물·실내 정책 | 해당 조건의 근거가 바뀔 때 재검수 |
| 사진·소개·시설 설명 | 권리·원천 필드를 확인해 갱신, 무관한 검수는 유지하는 방향으로 개선 |
| 행사 날짜·주최·공개 상태 | 변경 시 우선 검수, 월간 사이 급한 변경은 관리자 수동 실행 |
| 원천 비공개 | 명시적 비공개 표시 시 공개 제외, 이력 유지 |
| 변경 없음 | 재수집·재검수 생략 |

현재 코드에서는 변경된 콘텐츠의 모든 검수를 초기화한다. 위 항목별 유지/초기화 정책은 추천 개선안이며 구현 완료를 의미하지 않는다. 30일 검수 만료 규칙은 월간 실행일과 별개의 현재 규칙이며 항목별 유효기간 조정이 필요하다.

매월 모든 항목을 사람이 검수하지 않는다. 자동 변경 대조 후 필요한 항목만 확인한다. 월간 조회 실패·호출 한도 초과는 이전 공개 버전과 watermark를 유지하고 수동 재시도한다.
