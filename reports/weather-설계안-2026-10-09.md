# weather.guidejung.com 설계안 (2026-10-09)

> 공통 원칙: `reports/서비스-공통원칙-클릭체류.md` (클릭 유발·체류가 1순위)

목표: 검색으로 들어온 방문자가 **바로 답을 얻고, 다음 정보를 계속 눌러 보며 오래 머무르게** 만드는 날씨 사이트. trip과 서로 방문자를 주고받는 구조를 만든다.

## 1. 핵심 전략 (클릭·체류)
1. **3초 안에 답**: 첫 화면에 지금 날씨와 "오후 3시부터 비, 우산 챙기세요" 같은 한 줄 요약을 보여 준다.
2. **다음 행동 유도**: 요약 바로 아래에 "오늘 뭐 입지?", "우산 필요?", "빨래해도 될까?" 카드를 둔다. 누르면 상세 페이지로 넘어간다.
3. **손가락으로 넘기는 정보**: 시간별 예보는 가로로 넘겨 보고, 10일 예보는 펼쳐 보게 해서 스크롤과 터치를 늘린다.
4. **비교·순위 콘텐츠**: "어제보다 3도 낮아요", "오늘 전국에서 가장 맑은 곳 TOP 10", "이번 주말 비 안 오는 지역"처럼 계속 보게 만드는 목록을 만든다.
5. **trip과 순환**: 날씨에서 "이번 주말 맑은 지역의 가볼만한곳"으로, trip 상세에서 "이곳 날씨"로 이어 준다. 두 사이트가 서로 방문자를 보내는 구조다.
6. **재방문 장치**: 즐겨찾기 지역과 최근 본 지역 칩을 브라우저에 저장한다. 다시 들어오면 그 지역을 바로 보여 준다.
7. **롱테일 검색 페이지**: "강남구 날씨", "남이섬 날씨", "부산 주말 날씨" 같은 검색어마다 정적 페이지를 만든다.

애드센스 정책상 광고를 콘텐츠처럼 보이게 하거나 클릭을 유도하는 문구는 쓰지 않는다. 클릭은 콘텐츠로 유도한다.

## 2. 페이지 구성
| 경로 | 내용 | 노리는 검색어 |
|---|---|---|
| `/` | 내 위치 또는 최근 지역 날씨, 전국 지도·순위, 특보 띠 | 오늘 날씨 |
| `/{시도}` (17개) | 시도 요약 + 시군구 목록 + 시도 내 순위 | 서울 날씨 |
| `/{시도}/{시군구}` (약 250개) | 지금·시간별·10일·미세먼지·생활 카드·일출일몰 | 강남구 날씨 |
| `/{시도}/{시군구}/weekend` | 주말 날씨 + 그 지역 trip 추천 | 강남구 주말 날씨 |
| `/place/{trip id}` (trip 389곳, 늘어나는 만큼) | 여행지 좌표 기준 날씨 + trip 상세로 가는 링크 | 남이섬 날씨 |
| `/weekend` | 전국 주말 날씨, 맑은 지역 순위, 추천 여행지 | 주말 날씨 |
| `/ranking` | 가장 더운·추운·맑은·미세먼지 좋은 곳 | 오늘 가장 추운 곳 |
| `/guide/{주제}` | 옷차림, 우산, 빨래, 세차, 자외선 판단 기준 | 기온별 옷차림 |
| `/about`, `/data-policy`, `/privacy` | 안내, 출처(기상청·에어코리아), 광고·쿠키 고지 | — |

### 시군구 상세 화면 순서 (체류 동선)
1. 지금 날씨 큰 카드: 기온, 하늘, 체감, 어제와 비교, 한 줄 요약, 발표 시각
2. 생활 카드 4개: 옷차림, 우산, 미세먼지, 빨래·세차 (각각 상세로 이동)
3. **[광고 1]**
4. 시간별 예보 (가로로 넘기기, 48시간)
5. 10일 예보 (단기 3일 + 중기 4~10일)
6. 미세먼지·초미세먼지 상세 (측정소 기준, 시간 추이)
7. **[광고 2]**
8. "이번 주말 이 지역 가볼만한곳" (trip 카드 3개, trip으로 이동)
9. 주변 지역 날씨 (옆 시군구 칩) + 같은 시도 순위
10. 일출·일몰, 데이터 출처, 기준 시각

## 3. 데이터 (공공데이터포털 활용신청, 모두 무료)
| 우선 | API | 용도 | 갱신 |
|---|---|---|---|
| 필수 | 기상청_단기예보 조회서비스 | 초단기실황(지금), 초단기예보(6시간), 단기예보(약 3일) | 실황·초단기 매시간, 단기 하루 8회 |
| 필수 | 기상청_중기예보 조회서비스 | 4~10일 육상예보·기온 | 하루 2회(06·18시) |
| 필수 | 한국환경공단_에어코리아_대기오염정보 | 미세먼지·초미세먼지 | 매시간 |
| 권장 | 기상청_기상특보 조회서비스 | 특보 띠, 특보 페이지 | 수시 |
| 선택 | 기상청_생활기상지수 조회서비스 | 자외선 등 계절 지수 | 하루 2회 |
| 선택 | 한국천문연구원_출몰시각 정보 | 일출·일몰 | 날짜별 고정 |

- 단기예보는 위경도가 아니라 5km 격자(nx, ny)로 조회한다. 시군구와 trip 좌표는 기상청 공식 격자 변환식으로 미리 변환해 둔다.
- 중기예보는 예보구역 코드 단위라서, 시군구와 예보구역 대응표를 만든다.
- 개발계정 호출 한도는 API마다 다르다. 활용신청 후 포털에서 확인한 한도로 호출 계획을 확정한다.


## 3-1. 일일 호출 한도와 호출 계획 (2026-10-10 확인, 개발계정)
| API | 한도/일 | 호출 계획 | 예상/일 |
|---|---|---|---|
| 단기예보 | 10,000 | 시군구 대표 격자 약 250곳. 초단기실황 매시간(250×24=6,000) + 단기예보 하루 8회(250×8=2,000). 여행지 페이지는 소속 시군구 값을 사용("○○군 기준" 표시) | 약 8,000 |
| 중기예보 | 10,000 | 육상예보 구역 약 10곳 + 기온 지점(시도 대표) × 하루 2회 | 수백 |
| 기상특보 | 10,000 | 전국 특보 목록 매시간 | 약 24~100 |
| 생활기상지수(4.0) | 10,000 | 시도·시군구 지수, 하루 2회, 조회 시 캐시 | 수백 이하 |
| 출몰시각 | 10,000 | 시도 대표 지점 하루 1회 (또는 천문 공식으로 직접 계산해 호출 생략) | 17 이하 |
| **에어코리아 대기오염정보** | **500** | **시도별 실시간 측정정보를 "전국"으로 한 번에 조회**(측정소 전체 1회 호출) × 매시간 | **약 24~48** |
| **에어코리아 측정소정보** | **500** | **측정소 목록·좌표를 한 번만 받아 저장소에 정적 파일로 보관**, 월 1회 갱신 | **거의 0** |

- 단기예보가 가장 빠듯하다(80%). 여행지마다 격자를 따로 부르지 않고 시군구 값을 쓴다. 방문이 없는 지역은 미리 받지 않고 조회 시에만 받는 방식(온디맨드+캐시)으로 줄일 수 있다.
- Cloudflare 무료 플랜은 한 번 실행에 외부 호출이 50회로 제한된다. 미리 받기(Cron)는 50회 이하 묶음으로 나눠 여러 번 실행한다. 실제로 가능한지는 구현 후 측정한다.
- 트래픽이 커지면 에어코리아·단기예보는 운영계정 전환을 신청한다.

## 4. 구조와 배포
```
apps/weather/            Next.js 정적 페이지(지역·여행지 페이지 틀, SEO 문구)
apps/weather/worker/     Cloudflare Worker: /api/* 기상청·에어코리아 호출 + 캐시
apps/weather/wrangler.jsonc   별도 Worker(예: guidejung-weather), 도메인 weather.guidejung.com
packages/ui/             공통 디자인·애드센스·지역 코드 (trip과 공유)
packages/geo/            지역 ↔ 격자 ↔ 중기예보구역 ↔ 측정소 대응표 (신규)
```
- **trip과 다른 점**: 날씨는 하루에도 여러 번 바뀌어 컴퓨터에서 수집해 내보내는 방식이 맞지 않는다. 그래서 Cloudflare Worker가 기상청을 직접 호출한다.
- **캐시**: 응답은 다음 발표 시각까지 Cloudflare Cache에 저장한다. 같은 지역을 여러 사람이 봐도 기상청 호출은 발표당 1번이다.
- **미리 채우기**: Cron Trigger로 발표 직후 인기 지역(시도 17곳과 방문 상위 지역)을 미리 받아 둔다. 첫 방문자도 빠르게 보도록 하기 위해서다.
- **키 보관**: 기상청·에어코리아 키는 Worker 비밀값(`wrangler secret`)에만 둔다. 코드·브라우저에는 노출하지 않는다.
- **SEO**: 페이지 틀과 지역 소개 문구는 정적으로 만들고, 실시간 값은 같은 도메인의 `/api`에서 받는다. sitemap, RSS, robots, 네이버·다음 인증은 trip과 같은 방식으로 한다.
- **장애 대비**: 기상청 응답이 실패하면 마지막 캐시 값을 "○시 기준"으로 표시한다. 오래된 값은 "갱신 지연"으로 표시하고, 없는 값을 지어내지 않는다.
- **배포**: trip과 같은 저장소, 별도 Worker다. weather를 고쳐도 trip은 다시 배포되지 않는다.

## 5. 비용
- 기상청·에어코리아 API: 무료
- Cloudflare: 무료 플랜(Workers 하루 10만 요청, Cron, Cache)으로 시작
- 방문이 늘어 무료 한도를 넘으면 Workers 유료(월 $5)가 필요할 수 있다. 그때는 미리 알리고 승인을 받는다.
- 개발: Claude Pro 범위

## 6. 단계
1. **활용신청(사용자)**: 단기예보, 중기예보, 에어코리아 대기오염정보 (+특보)
2. **기반**: 지역·격자·예보구역·측정소 대응표, Worker API와 캐시, 키 등록
3. **MVP**: 메인, 시도·시군구 페이지, 생활 카드, 주말·순위, 애드센스, SEO 파일
4. **trip 연계**: weather에 trip 추천 카드, trip 상세에 "이곳 날씨" 위젯 (서로 링크)
5. **확장**: 여행지 날씨 페이지, 특보, 생활지수, 가이드 글
6. **도메인 연결(사용자)**: Cloudflare에서 weather.guidejung.com을 새 Worker에 연결하고, Search Console·네이버에 등록

## 7. 확인 필요(미확정)
- 각 API의 개발계정 일일 한도 (활용신청 후 확인)
- 중기예보구역 코드표와 에어코리아 측정소 목록의 최신본
- Worker 무료 플랜 CPU 시간 안에서 응답 처리가 가능한지 (표본으로 측정)
