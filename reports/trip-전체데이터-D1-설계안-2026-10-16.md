# trip 전체 데이터(D1) 전환 설계안 — 2026-10-16

목표: 한국관광공사 TourAPI 전체 데이터(현재 4개 유형, 수만 건 추정)를 trip.guidejung.com에 올린다.
현재 구조(장소마다 HTML을 미리 만드는 정적 사이트)는 996건에 파일 6,230개·174MB·검색 파일 1.7MB라
3,000건 상한(10/7 Claude가 정함)을 넘기면 파일 수 한도·빌드 시간·검색 속도가 무너진다.

## 1. 클릭·체류 설계 (먼저)
- 데이터가 수십 배로 늘면 "내 주변 20km", 지역 페이지, 상세의 "주변에서 함께 둘러볼 곳"이 거의 모든 위치에서 꽉 찬다
  → 상세 → 주변 → 상세로 이어지는 체류 고리가 강해진다.
- 상세 페이지 하단 '주변 4곳'을 **8곳 + 유형별(관광지·문화시설·레포츠·축제) 탭**으로 늘린다(데이터가 충분해져서 가능).
- 지역 페이지는 정보 많은 순 + 유형 칩(관광지/문화시설/레포츠/축제) — 건수가 많아져 고를 거리가 생긴다.
- 검색은 서버(D1)에서 해서 첫 화면이 빨라진다(지금은 1.7MB 검색 파일을 먼저 받아야 결과가 보임 → 전체면 수십 MB).
- 사이트 간 연결(날씨·교통·충전소 카드), 광고 위치는 그대로 유지.

## 2. 구조
| 부분 | 지금 | 바뀐 뒤 |
|---|---|---|
| 상세 페이지 `/place/{id}`·`/festival/{id}` | 빌드 때 HTML 미리 생성 | **Worker가 D1에서 읽어 HTML 생성**(같은 React 컴포넌트를 서버에서 렌더) + 데이터센터 캐시 |
| 검색·목록 결과 | 브라우저가 search-index.json 전체를 받아 검색 | **`/api/search`**(Worker → D1 SQL) |
| 메인·목록·지역·안내 페이지 | 정적 | 정적 유지(검색엔진용 첫 24개 카드는 빌드 때 작은 데이터 파일로) |
| sitemap | 정적 1개 | 사이트맵 묶음(index) + D1에서 4만 건씩 나눠 생성 |
| rss | 정적 | D1 최신 변경 50건 |
| 데이터 | `trip.json` 전체(git) | 전체는 **D1 `guidejung-trip`**, git에는 메인·목록 빌드용 작은 파일만 |

- Worker 설정: 루트 `wrangler.jsonc`(Worker `data-platform`)에 `main`·D1 바인딩 추가, `run_worker_first`: `/api/*`, `/place/*`, `/festival/*`, `/sitemap*`, `/rss.xml`.
- D1 표: `places`(id·kind·이름·지역·좌표·날짜·품질점수·조건 4개 열·카드용 JSON·상세 JSON·갱신시각), `regions`, `meta`(공개 상태·데이터 버전). 색인: 유형+품질, 지역, 위도, 날짜.
- 검색 규칙은 지금 `packages/ui/src/search.ts`와 같게(유형·지역·조건·검색어·날짜·반경, 정렬: 거리 → 품질 → 이름).

## 3. 데이터 올리기(컴퓨터)
- `collect-trip.bat`: 상한 3,000 → 해제(목표 입력은 그대로). 전체는 한 번에 말고 **1만 건씩 늘려 가며**(수집 상태 파일이 커져 느려지는지 확인).
- `export-site.bat`: ① 작은 빌드용 파일 git push(지금처럼) ② 전체를 D1에 올림(`npx wrangler d1 execute --remote`, 컴퓨터에서 **처음 한 번 `npx wrangler login`** 필요).
- 비용: D1은 유료 플랜 포함(저장 5GB·읽기 월 250억 행). 5만 건 × 약 5KB = 약 250MB. 추가 비용 없음.
- TourAPI: 새 항목 1건 약 5회 호출 → 5만 건이면 약 25만 회 = 하루 10만 한도로 약 3일.

## 4. 단계
1. D1 만들기(사용자, 2분) → ID 전달.
2. Worker + D1 표 + 올리기 스크립트 + 상세 서버 렌더 + `/api/search` (지금 996~3,000건으로 시험, 정적 상세와 결과 비교).
3. 목록·검색을 `/api/search`로 전환, 정적 상세·search-index.json 제거, 사이트맵 묶음.
4. 수집 상한 해제 → 1만 건씩 수집·올리기 → 전체.
5. 클릭·체류 보강(주변 8곳·유형 탭·지역 유형 칩).

## 5. 위험·확인할 것
- Next.js 정적 페이지와 Worker가 만든 상세 페이지가 섞임: 상세는 Next 런타임 없이 순수 HTML(링크는 일반 이동). 광고·Clarity·인증 태그는 같은 head를 씀.
- 수집 프로그램이 수만 건에서 느려질 수 있음(상태 파일·DB 적재) → 1만 건 단위로 확인.
- 검색엔진: 상세 주소(URL)는 그대로라 기존 색인 유지.
- TourAPI 전체 건수는 미확인(첫 목록 호출의 totalCount로 확인). 숙박·음식점·쇼핑·여행코스는 지금 수집 대상이 아님 → 넣을지 사용자 결정.
