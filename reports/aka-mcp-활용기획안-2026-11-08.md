# mcp.aka.page(다이소·편의점 재고 MCP) 활용 기획안 — 2026-11-08

> 한 줄 결론: **"지금 그거 근처 어디 있어?"**(핫팩·우산·상비약·영화 좌석)를 내근처 사이트의 **실시간 재고 위젯**으로 먼저 붙이고, 클릭이 나오면 새 사이트 **'내근처 재고'**로 키운다. 다만 이 서비스는 **다이소·편의점의 내부 API를 분석해 다시 호출하는 개인 오픈소스 프로젝트**라서, ① 숫자를 저장·공개(정적 HTML·사이트맵)하지 않고 ② 방문 때만 호출하며 ③ 운영자에게 먼저 알리고 시작하는 조건을 권장한다.

## 1. 클릭·체류 설계 (맨 앞)

| 사람이 오는 순간 | 3초 답 (첫 화면) | 다음 클릭 |
|---|---|---|
| 겨울 아침, 핫팩이 급함 | 📍 **김포시 다이소 14곳 중 9곳에 핫팩 있어요** · 가장 가까운 **풍무로점 19개** | 매장 상세(길찾기) → 다른 종류(대형·15개입) → 근처 편의점 |
| 비 예보 70% (날씨 사이트) | ☔ **오늘 비 와요 · 근처 편의점 우산 있는 곳 3곳** | 편의점 재고 → 주차장·길찾기 |
| 밤 11시, 약국 닫음 (약국 사이트) | 🌙 **문 연 약국 없음 → 근처 편의점 해열제 있는 곳 2곳** (편의점 상비약 재고) | 응급실(병원 사이트) → 내일 여는 약국 |
| 비 오는 주말 (여행·날씨) | 🎬 **근처 영화관 오늘 남은 좌석** · 롯데시네마 ○○ 14:20 32석 | 상영 시간표 → 주변 맛집(여행) |
| 수능·한파 등 시기 페이지 | 시기 페이지 안 '지금 근처에서 살 수 있는 곳' 칸 | 매장 상세 |

- 체류: 상품 칩(핫팩 6종·우산·건전지·충전 케이블·마스크…)을 누를 때마다 같은 동네 재고가 바로 바뀌고, 매장 카드 → 매장 상세(진열 위치까지) → 다른 사이트 연결 카드로 이어짐.
- 클릭은 콘텐츠로만 유도하며, 광고 근처에 '눌러 보세요'류 문구는 쓰지 않는다(애드센스 정책).

## 3. 위험과 판단

| 위험 | 내용 | 대응(권장) |
|---|---|---|
| 원천 약관·데이터베이스권 | 공식 제휴 API가 아니라 내부 API를 다시 부르는 방식. 다이소·편의점 약관은 자동 수집·재배포를 막을 가능성이 높고, 재고·매장 목록을 통째로 모아 공개하면 데이터베이스 제작자 권리(저작권법 제93조) 문제 소지 — **확실하지 않음(약관 원문 미확인)**. 네이버 플레이스 크롤링을 하지 않기로 한 것과 같은 성격 | 숫자를 **저장·정적 HTML·사이트맵·JSON-LD에 넣지 않음**. 방문자가 볼 때만 불러오고 출처('다이소몰 재고, daiso-mcp 경유') 표시. 상품·매장 전체 목록 페이지(예: '다이소 핫팩 124종 가격표')는 만들지 않음 |
| 남의 무료 서비스에 기대기 | 개인이 운영, 언제든 멈추거나 막힐 수 있음. 우리 트래픽(하루 수천 명)이 분당 한도를 함께 씀 | ① 운영자에게 먼저 알림(GitHub 이슈 또는 `submit_request`) ② near Worker를 거쳐 **같은 지역·상품은 10분 데이터센터 캐시로 합치기**(상대 부담↓, 방문자 IP도 안 넘어감) ③ 실패하면 위젯만 조용히 숨김 |
| 직접 운영(포크) | MIT라 우리 Worker로 띄울 수 있지만, 그러면 **우리가 직접 다이소 내부 API를 부르는 주체**가 됨 | 하지 않음 |
| 정확도 | 비공개 수량·지난 수치가 섞임 | 비공개는 '?' + '매장에 전화' (0과 구분), '○분 전 확인' 표시 |
| 위치 | 위치정보법 원칙(서버엔 칸 중심만) | 정확한 좌표는 보내지 않음. `pickArea`·`nearest()`로 고른 **시군구 이름**만 keyword로 보냄 → 거리는 휴대폰에서 `here(pos)`로 계산 |

## 4. 활용안

### 4-1. 1단계: 공용 위젯 `.gj-stock` (권장 시작점)
- `packages/ui/src/live.ts`의 `LIVE_JS`에 추가(블로그 후기 `.gj-blog`와 같은 방식, 보이기 직전 호출). `data-item="hotpack|umbrella|..."`, `data-chain="daiso|gs25|cu|..."`.
- 서버: near Worker `/api/stock?item=&area=` → aka.page REST 호출 → 필요한 칸만(매장 이름·주소·좌표·수량·영업시간) → `caches.default` 10분, `*.guidejung.com` Origin만.
- 상품 묶음은 우리 표 `ITEMS`(item → 다이소 상품 ID 2~6개·편의점 검색어)로 관리. 상품 ID가 바뀌면 상품 검색으로 다시 찾기(하루 1회 Actions가 확인, ID만 저장 — 재고 숫자는 저장 안 함).

| 붙일 곳 | 위젯 | 조건 |
|---|---|---|
| 날씨 첫 화면·지역 | ☔ 우산(편의점·다이소) | 12시간 안 강수확률 60%↑일 때만 |
| 날씨 미세먼지 | 😷 마스크 | 나쁨 이상일 때만 |
| 약국 첫 화면·상세 | 💊 편의점 상비약(해열진통제·소화제) | 근처 문 연 약국이 없거나 밤 22시~ |
| 시기 페이지 `/season/winter-car` | 🧊 성에 제거제·워셔액(다이소) | 기간 동안 |
| 새 시기 페이지 `/season/cold-wave`(한파) | 🔥 핫팩 6종 | 11~2월, 한파특보 때 맨 위 띠 |
| 동물병원 상세 | 🐾 배변패드·간식(다이소) | 상시(아래쪽) |
| 여행 '비 오는 날 실내'·주말 | 🎬 근처 영화관 오늘 남은 좌석 | 강수확률 60%↑ 주말 |
| 모아보기(near) 카드 | 🏪 '근처 다이소 ○곳·지금 영업 중' | 상시(17번째 카드) |

※ 편의점 상비약은 약사법상 편의점 판매 품목(안전상비의약품)이라 재고 표시만 하고 복용 안내는 하지 않음. GS25·CU에서 상비약 검색이 되는지는 **아직 시험 안 함**(다음 단계 첫 확인).

### 4-2. 2단계: 새 사이트 '내근처 재고' (1단계 클릭을 보고 결정)
- 이름(안) **내근처 재고 · "그거 지금 어디 있어?"** · `stock.guidejung.com`(안).
- 정적 페이지(SEO·GEO·AEO용 — **우리가 쓴 내용만**): 상황별 `/item/{hotpack|umbrella|battery|charger|mask|medicine|pad}`(고르는 법·쓰는 법·주의·FAQ·HowTo JSON-LD, 숫자 없음), `/region/{시군구}`(그 동네 매장 수는 넣지 않고 다른 내근처 사이트 연결·위젯), 계절 띠.
- 실시간: 3초 답 `NearStock`(상품 칩 → 시군구 매장별 재고, 가까운 순), 매장 상세는 우리 페이지 없이 **다이소·편의점 공식 페이지로 연결 + 길찾기**(상세를 만들면 매장 DB 재공개가 되므로).
- 위험: 정적 내용이 얇으면 색인이 안 될 수 있음(11/5 색인 점검과 같은 문제) → 상품마다 우리만의 안내 2,000자 이상이 가능할 때만 연다.

### 4-3. 쓰지 않을 것
- **오피넷·네이버 장소 검색**: 이미 주유소 사이트(오피넷 직접)·NAVER API HUB로 하고 있어 필요 없음.
- **올리브영·일본 다이소·가격 비교**: 내근처 '급할 때 동네' 주제와 거리가 멀다.
- **MCP 프로토콜 자체**: 사이트에서는 REST(JSON)만 씀. MCP는 Claude 세션에서 확인·조사용(오늘 핫팩 표처럼).
