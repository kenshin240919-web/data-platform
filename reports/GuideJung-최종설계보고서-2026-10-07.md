# GuideJung 여행정보 플랫폼 — 최종 설계보고서

## 1. 확정 범위와 보호 원칙

기존 guidejung.com의 서버·WordPress·DB·DNS·Analytics·Search Console 설정을 변경하지 않는다. 신규 여행 플랫폼은 별도 애플리케이션·DB·배포 환경에서 운영한다. GitHub 업로드, 서버 배포, 도메인 연결은 사용자가 최종 확인한 후 직접 진행한다.

home.guidejung.com의 역할과 화면은 이번 범위에서 제외한다. 기존 home 앱은 제거했으며 향후 별도 설계한다. traffic·academy·charge·weather는 확장 구상만 유지한다.

## 2. 현재 아키텍처

```text
여행정보 Next.js 앱 → FastAPI 조회·관리 API → 전용 PostgreSQL
                                         ↑
TourAPI → 비공개 RAW → 정규화·검증 → 데이터 버전 → 공개 조회
                         ↑
                 관리자 내용검수·승인
```

| 구성 | 구현 및 운영 방향 |
|---|---|
| 화면 | Next.js App Router, React, TypeScript, 모바일 대응 |
| 공통 UI | 브랜드·검색·목록·상세·지역·검수 컴포넌트 |
| API | FastAPI, SQLAlchemy, 관리자 토큰 인증 |
| DB | 전용 PostgreSQL, core/trip/ingest/ops 영역 |
| 수집 | Python, 호출 예산·체크포인트·실행 잠금 |
| 지역 | 공식 법정동 코드 버전과 원천 지역코드 매핑 |
| 주변 검색 | 현재 Haversine 직선거리 계산; 대규모 운영 시 PostGIS 공간 인덱스 적용 |
| 배포 준비 | Docker Compose·프록시·월간 systemd 동기화 설정 |

로컬 여행 화면은 http://localhost:3101/, API는 http://127.0.0.1:8100/이다. DB는 별도 로컬 포트 55432를 사용한다. 로컬 주소는 다른 기기에서 접속하는 공개 서비스 주소가 아니다.

## 3. 브랜드와 화면 구조

상단 및 하단 브랜드는 **🚗 여행정보**다. 브랜드와 서비스 홈 링크는 여행 앱 첫 화면으로 이동한다. 기존 통합 홈 화면으로 돌아가는 연결을 제거했다.

| 화면 | URL | 주요 내용 |
|---|---|---|
| 여행 홈 | / | 여행 검색, 장소·축제 목록 |
| 가볼만한곳 | /place | 관광지·문화시설·레포츠 |
| 축제·행사 | /festival | 일정·장소·요금, 종료 상태 |
| 지역 | /region | 지역별 여행정보 |
| 날짜 | /today, /weekend | 오늘·주말 일정 |
| 조건 | /free, /kids, /pet, /indoor | 근거가 확인된 조건만 포함 |
| 검색 | /search | 이름·지역·종류·날짜·조건 검색 |
| 장소 상세 | /place/{id} | 사진·주소·운영·시설·출처·확인일 |
| 행사 상세 | /festival/{id} | 일정·주최·공식 링크·시설·주변 장소 |
| 관리자 | /admin | 수집 현황·검수 목록·승인/반려·변경 확인 |
| 안내 | /about, /data-policy, /privacy | 여행 서비스 소개·출처·정보 처리 안내 |

상세에는 운영시간, 휴무, 입장·이용요금, 주차·주차요금, 수용인원, 이용연령, 연락처, 주최·주관, 반복 시설 안내와 반려동물 정책을 표시한다. 미제공 값은 ‘확인 필요’다. 이동시간은 추정하지 않으며 주변 거리는 직선거리임을 표시한다.

## 4. 데이터 규모와 수집 결과

사용자 지시에 따라 현재는 **총 200건**까지만 수집했다.

## 5. DB·버전·출처 설계

core는 공통 지역·장소·원천 연결·사진·분류를 관리한다. trip은 장소 프로필과 행사 일정을 관리하며 조건과 시설은 프로필 스냅샷 및 근거 데이터에 보존한다. ingest는 원본 응답과 데이터 버전을, ops는 검증 결과·수집 로그·색인 정책을 저장한다.

원천 ID와 플랫폼 내부 UUID를 구분하고 동일 원천 ID의 변경은 새 데이터 버전에 반영한다. 증분 수집 시 변경 없는 항목도 새 버전에 유지한다. 검증 실패 시 기존 공개 버전을 유지하며 원본 및 검수 이력을 보존한다.

최초 설계의 모든 관계 테이블을 별도로 구현한 것은 아니다. 시설·조건은 현재 스냅샷 중심이며 행사 series/회차·복수 개최 장소의 완전한 관계 모델, 도로명/지번 분리 정규화, 법정동/행정동 다대다 매핑의 실데이터 보강은 후속 범위다.

## 6. 내용검수와 사진 정책

200건의 TourAPI 공통·소개 응답을 새로 조회해 원천 ID, 명칭, 주소, 지역코드, 설명, 운영정보, 요금과 일정을 대조했다. 시설·사진·반려동물 정보는 이번 수집 시 확보한 공식 응답으로 확인했다. 사용자 위임에 따라 검수자는 ‘Codex · 사용자 위임 검수’로 기록했다.

운영기관 홈페이지는 이름 확인 75건, 내용 확인 불충분 72건, 미제공 38건, 조회 실패/차단 15건이다. 홈페이지에 이름이 있다는 사실만으로 모든 운영조건을 독립 검증했다고 처리하지 않았다.

- 요금 미제공 72건, 운영시간 미제공 4건, 휴무 미제공 53건은 확인 필요로 유지했다.
- 명확한 근거로 기본 입장 무료 82건, 반려동물 가능 4건, 실내 1건을 표시했다. 아이 동반 적합성은 추정하지 않았다.
- 관광지의 반복 시설 응답에 들어 있던 입장료 누락을 수정했다.
- 세 박물관의 휴관 예외·연휴 안내를 공식 홈페이지 기준으로 보강했다.
- 영흥도 몽돌해변의 다른 섬 설명은 제외하고 실제 위치 확인 안내를 표시했다. 하양목장/휘바핀란드와 노원 행사 명칭 차이도 공개 설명에 표시했다.
- 전년도 먹거리 안내를 올해 확정 내용으로 인정하지 않았으며 종료 행사 12건은 과거 일정으로 구분했다.

사진은 HTTPS 한국관광공사 원본과 개별 공공누리 1·3유형 권리코드를 확인한 경우에만 사용한다. 출처·라이선스를 표시하며 3유형 사진은 자르거나 변형하지 않는다. 권리정보가 없는 사진은 임의 대체하지 않는다.

검수 승인은 공식 원천에 충실한 공개 내용 확인을 뜻한다. 현장 영업 확인, 누락 요금의 독립 확인, 상호 동일성 확정, 좌표의 행정구역 공간 경계 검증은 완료하지 않았다. 원천이 불일치하는 항목은 이를 표시한 제한적 공개 상태다.

## 7. 월간 변경 동기화

**매월 1일 오전 6시 KST, 월 1회**로 서버용 설정을 준비했다. 실제 예약 실행 등록은 서버 배포 때 적용한다.

areaBasedSyncList2의 변경 목록에서 현재 수집한 ID만 확인한다. 신규 장소를 자동 추가하지 않는다. 변경된 항목의 상세·시설·사진·정책을 갱신하고 재검수 대기로 돌린다. 변경 없는 항목을 일괄 재검수하지 않는다. 원천 비공개 표시는 공개 검색·상세에서 제외하고 이력은 보존한다.

성공 시에만 watermark를 갱신하며 날짜 경계 누락을 줄이기 위해 하루 겹침 조회를 한다. 실패 시 기존 공개 버전을 유지한다. 현재는 변경 레코드 전체의 검수 상태를 초기화한다. 바뀐 필드만 선택적으로 재검수하는 기능은 후속 개선이다.

월간 수집은 갑작스러운 취소·운영 변경을 즉시 반영하지 못한다. 방문자는 공식 링크로 최종 안내를 확인한다. 운영계정 호출 한도와 대량 월간 변경 목록의 페이지 상한 검증은 배포 전 확인 항목이다.

## 8. 보안·백업·SEO

API 키와 ADMIN_TOKEN은 서버 환경변수로 관리한다. .env, 로컬 DB 자격증명, runtime 원천·검수 파일은 Git에서 제외한다. 키를 브라우저 코드나 원천 요청 로그에 포함하지 않는다. 관리자 현황·검수·동기화 작업은 토큰 인증으로 제한한다.

로컬 DB 백업을 별도 임시 DB에 복원해 주요 테이블 건수를 대조했다. 운영 환경의 자동 백업·보관 기간·외부 저장소·복구 목표는 서버 선정 후 설정 및 복구 시험이 필요하다.

현재 SEO_ENABLED=false이며 색인 허용은 0건이다. 승인만으로 SEO를 활성화하지 않는다. 충분한 상세정보·품질·신선도·필수 검증을 확인한 뒤 색인을 선별 허용한다. 검색 파라미터·희소 목록은 noindex 정책을 유지한다. canonical·robots·sitemap은 여행 호스트 기준이며 기존 guidejung.com의 설정은 변경하지 않는다.

## 10. 비용·확장 원칙 및 참고자료

현재 수집·정규화·월간 동기화에는 유료 AI API 호출이 필요하지 않다. AI API 등 추가 유료 호출이 필요해지면 사용 전에 사용자에게 비용을 알리고 승인을 받는다. 개발·검수 지원은 가능한 구독 기반 도구를 우선 사용한다. 사용자 구독은 Claude Pro, ChatGPT Plus, Genspark AI Plus이며 외부 API 비용과 별개로 취급한다.

초기 보고서의 월 50~60달러 인프라 예산은 2026-10-06의 특정 서버·관리형 DB 조합에 대한 계획치다. 현재 계약하거나 발생한 비용이 아니며 trip 단독 배포의 최종 견적은 서버 선택 시 다시 산정한다.

확장은 여행 데이터 품질과 변경 동기화를 안정화한 뒤 필요한 서비스부터 별도 설계한다. 공통 region_id·place_id·출처·기준시각·데이터 버전을 재사용하되 기존 사이트와 환경을 공유하지 않는다.
